## 1. Цель работы

Реализовать функциональность создания файлового образа диска и сохранения в него зашифрованных файлов. Освоить работу с блочными устройствами на уровне файлов, низкоуровневое форматирование и разметку диска, структуры данных для хранения метаинформации и полный цикл работы с защищённым хранилищем данных.

## 2. Что реализовано

Программа `secure_copy` поддерживает три операции:

| Операция | Описание |
|----------|----------|
| `-add`   | Добавление файлов и директорий в образ (с шифрованием) |
| `-list`  | Просмотр списка файлов в образе |
| `-get`   | Извлечение и расшифровка конкретного файла из образа |

### Ключевые возможности

- **Шифрование RC4** — поточный шифр, ключ = мастер-ключ + соль (16 байт `/dev/urandom` на файл)
- **Защита ключа** — `mmap` + `mlock` (запрет свопа на диск) + `mprotect(PROT_NONE)` после использования + затирание `memset` перед `munmap`
- **Защита S-блока** — трёхуровневая: opaque-структура `rc4_ctx`, `static` KSA/PRGA, `volatile`-memset при уничтожении
- **Параллельная обработка** — до 5 потоков, каждый шифрует свой файл чанками и пишет через `pwrite`
- **Чанковая запись** — файл читается/шифруется/пишется кусками по 64 КБ, без загрузки целиком в память
- **Рекурсивный обход** — добавление директорий с вложенностью до 4 уровней
- **Перезапись дубликатов** — если файл с таким именем уже есть в образе: при совпадении размера — in-place перезапись, при различии — полная пересборка образа
- **Обработка ошибок** — программа не аварийно завершается при ошибках (возврат 1)

## 3. Формат образа

Файл образа — бинарный, **little-endian**, без единого заголовка, состоит из последовательных записей:

```
[4B content_size][4B name_len][16B salt][nB name][mB encrypted]
```

| Поле | Размер | Описание |
|------|--------|----------|
| `content_size` | 4 байта | Размер зашифрованного содержимого |
| `name_len` | 4 байта | Длина имени файла |
| `salt` | 16 байт | Случайная соль для этого файла |
| `name` | `name_len` байт | Имя файла (с ведущим `/`, например `/dir/file.txt`) |
| `encrypted` | `content_size` байт | Зашифрованное RC4 содержимое |

Такой формат гарантирует совместимость — образ, созданный на одной системе, корректно читается на другой.

## 4. Как работает

### 4.1 Добавление файлов (`-add`)

1. **Сбор файлов** — main-поток собирает список файлов (рекурсивно обходя директории, глубина ≤ 4)
2. **Чтение существующего образа** — если образ уже есть, читаются все записи
3. **Предрасчёт offset'ов** — для каждого файла вычисляется `file_size` (через `stat`) и `file_offset` (позиция в образе). Если файл новый — дописывается в конец. Если уже есть с тем же размером — in-place перезапись. Если размер отличается — полная пересборка (fallback).
4. **Создание образа** — `open` + `ftruncate` до общего размера (файл сразу нужного размера, заполнен нулями)
5. **Запись существующих записей** — main-поток пишет старые записи (не перезаписанные) через `pwrite`
6. **Параллельная обработка** — до 5 потоков (pthread). Каждый поток:
   - Открывает исходный файл
   - Создаёт ключ (mmap + mlock + mprotect)
   - Инициализирует потоковый RC4 (rc4_init → KSA)
   - Пишет заголовок записи через pwrite
   - В цикле: читает 64 КБ из файла → шифрует на месте через rc4_encrypt → pwrite в образ
   - Очищает всё (munmap, rc4_destroy, mprotect+затирание+munmap ключа)
7. **Очистка** — закрытие файлов, освобождение памяти

### 4.2 Просмотр списка (`-list`)

1. Чтение образа с диска (`read_image`)
2. Сортировка записей по имени (лексикографически, через индексы)
3. Вывод: `имя_файла<TAB>размер`

### 4.3 Извлечение файла (`-get`)

1. Чтение образа с диска
2. Поиск записи с указанным именем (точное совпадение через `strcmp`)
3. Создание ключа (mmap + mlock) = мастер-ключ + соль из записи
4. Расшифровка через `rc4_crypt` (RC4 симметричен — XOR теми же keystream-байтами)
5. Запись расшифрованных данных в выходной файл
6. Очистка

### 4.4 Параллельность

- Используется до 5 потоков (`#define MAX_THREADS 5`)
- Единственный мьютекс — в очереди задач (`work_queue`), только для атомарного взятия следующего индекса (`q->next++`)
- Запись в образ не требует мьютекса — offset каждого файла рассчитан заранее, потоки пишут в непересекающиеся диапазоны через `pwrite`

## 5. Примеры команд

### 5.1 Добавление отдельных файлов

```bash
./secure_copy -add -key "secret" -image disk.img file1.txt file2.txt
```

### 5.2 Добавление директории (рекурсивно, до 4 уровней)

```bash
./secure_copy -add -key "secret" -image disk.img mydir/
```

### 5.3 Список файлов в образе

```bash
./secure_copy -list -image disk.img
```

Вывод (отсортирован по имени):
```
/dir/file.txt	1024
/file1.txt	512
/file2.txt	256
```

### 5.4 Извлечение файла

```bash
./secure_copy -get -key "secret" -image disk.img -out restored.txt /file1.txt
```

### 5.5 Массовое извлечение (скрипт `extract.sh`)

```bash
bash extract.sh disk.img "secret" output_dir/
```

## 7. Особенности macOS

- `mlock` / `munlock` — доступны из `<sys/mman.h>`, работают стандартно
- `MAP_ANONYMOUS` — определён в `<sys/mman.h>`, требуется флаг `-pthread` для линковки pthreads
- `pwrite` — работает идентично Linux
- Система сборки — `clang` из Xcode, флаги `-Wall -Wextra -pedantic`
- Для генерации соли используется `/dev/urandom` (доступен)
